# 安全与隐私

按触及的数据、能力和攻击入口检查；普通布局修改不自动触发全项目安全重构。涉及 Play 申报时参考 [google-play-release.md](google-play-release.md)，不由安全检查自动启动发布流程。

## 数据与权限

- 只收集完成明确功能所需数据，记录用途、接收者、保存位置、保留与删除方式；分析、广告、崩溃和第三方 SDK 的数据访问也在范围内。
- 在相关用户操作需要时请求权限，提供拒绝、撤销和永久拒绝后的合理路径；可以使用系统选择器／授权机制完成任务时，不默认索取广泛存储、通讯录或位置权限。
- 先核对系统权限与 Play 政策适用范围，不能通过声明一个权限就宣称有资格使用敏感能力。
- 私有数据存储、备份／导出和日志要一起检查；私有目录不等于所有数据已加密，DataStore 不等于加密凭据库。

## 凭据与网络

- 不在源码、资源、BuildConfig 或 App 包中放可保密的服务端密钥。客户端标识类 API key 依服务要求限制用途，不声称混淆可以保密。
- 凭据按威胁和生命周期选择平台支持的安全存储；需要保护密钥时使用 Android Keystore 等平台能力并处理失效／重建。不要自创密码算法或采用已废弃库作为永久模板。
- HTTPS 与证书校验保持有效，禁止信任全部证书／主机；调试证书与明文例外限定 debug 范围。证书固定仅在有明确威胁模型及轮换策略时采用。
- 日志、崩溃上下文和网络拦截器需脱敏；不能记录密码、令牌、完整个人信息或把认证 URL 暴露到分析服务。

## 平台入口与身份

- exported 组件、Intent、PendingIntent、URI、ContentProvider 和 FileProvider 按所需可见性最小配置，校验调用方、输入及授予范围。
- 深链／App Links 参数不能直接当可信身份或授权。需要服务端验证的会话、支付和资源权限不能只靠 UI 隐藏或客户端布尔值。
- WebView 在确有需求时启用功能，校验导航目标和 JS bridge 的暴露面；不默认打开文件访问、任意域跳转或给不可信页面注入敏感接口。
- 登出、账号切换和删除处理令牌、在途请求及本地敏感数据；账号删除不等于退出登录、清缓存或仅将账号停用。

## 验证与交付

检查相关 release 配置和合并 Manifest、权限拒绝／撤销、越权输入、错误账号和日志输出。记录实际修复和剩余限制，不能仅凭使用某个库宣称应用安全。政策申报需要依赖真实数据流和服务端事实，不能编造隐私承诺。

依据：[Android 安全实践](https://developer.android.com/privacy-and-security/security-best-practices)、[Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469)、[账号删除政策](https://support.google.com/googleplay/android-developer/answer/13327111)。这不是所有业务场景的完整安全审计。
