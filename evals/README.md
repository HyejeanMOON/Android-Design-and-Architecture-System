# 评测边界与执行

这里的样例用于 Review／修复验证，不是生产模板，也不是 Android App。规则主体与评测答案分开，避免评估者直接读答案后被误认为具备发现能力。

## 三组真实源码切片

| 用例 | 内容 | 可执行边界 |
| --- | --- | --- |
| [XML](cases/xml/prompt.md) | Fragment、layout、资源与外部字段键；含生命周期和 typo 问题及正确对照 | XML 可解析；Fragment 需接入独立 Android 测试项目才能编译／做泄漏运行验证 |
| [Compose](cases/compose/prompt.md) | Route、ViewModel 接口、状态与显示；含重组副作用及正确对照 | 需 Android／Compose 编译与 UI 环境，本仓库不提供 App 工程 |
| [状态](cases/state/prompt.md) | 可供 ViewModel 使用的纯 Kotlin 状态组件；含乱序、会话及刷新失败问题 | 可用 Kotlin/JDK 独立编译并运行确定性行为测试；不证明线程安全或 Android 生命周期正确 |

每组 `input/` 是待评估输入，`fixed/` 是一种参考修复，不要求模型生成完全相同代码。评分以实际行为、证据和范围控制为准。

## 本地回归

```sh
python3 scripts/run_regressions.py --kotlinc /path/to/kotlinc --java /path/to/java
```

脚本在临时目录编译；要求缺陷版与修复版均能编译、缺陷版在五个特定行为场景失败且正常路径通过、修复版六场景全部通过。编译失败不能冒充发现缺陷；缺工具返回未执行状态，不下载或安装工具链。

状态检查使用可控的调用完成顺序，不靠 sleep、网络或实现文本匹配。XML 检查只是格式解析，不等于 Android 资源编译。参考修复的 Android API／绑定仍需独立工程及设备验证。

评估隔离副本里的状态修复时，加 `--candidate /isolated/SearchModel.kt`，该模式要求候选六场景全部通过；默认模式仍要求原始缺陷版失败。这样不会把成功修复 input 后不再出现预期失败误判为回归，也不需要改评分脚本或测试。

## 人工／模型行为评测

1. 在隔离目录向评估者只提供所选用例的 `input/`、`prompt.md` 与技能目录；不提供 `fixed/`、[oracle.json](oracle.json)、本文或历史答案。
2. Review-only 模式记录原始输出，不允许修改／提交；修复模式仅修改隔离副本，执行相关行为验证。不要把本仓库的评分文件当代理指令。
3. 评估结束后由评审者对照 oracle 的语义核对位置、触发、影响、证据和建议。记录漏报、误报、外部键误改、无关重构、假称验证及超范围操作；不能靠关键词／问题数量自动给通过。
4. 对正确对照或已修复版重复评估以观察误报；修复后运行同一行为回归，确认没有通过改测试降低门槛。
5. 记录日期、模型／版本、技能版本、任务与输入版本、实际工具、输出和结果。不把作者自审称为独立模型评测，不未经授权启动代理或上传代码。

更多跨领域场景仍见 [scenarios.md](scenarios.md)，按高风险或规则变更选择，不要求每次文案改动运行全部场景。当前实际执行范围见 [0.5.0 记录](results/0.5.0-local.md)。
